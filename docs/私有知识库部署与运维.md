# 私有知识库部署与运维

## 1. 能力边界

每个登录用户最多创建 5 个知识库，每个知识库最多保存 20 份文档。单文件上限为 10MB，支持 PDF、DOC、DOCX 和 Markdown。PDF 必须包含可复制文字，不支持扫描件 OCR 和加密 PDF。

MySQL 是知识库、文档归属和异步任务状态的事实来源；`backend/uploads/knowledge` 保存原文件；`backend/data/chroma` 保存可重建的向量索引。三者必须一起纳入备份策略。

## 2. 环境变量

复制 `backend/.env.example` 为 `backend/.env`，至少配置：

```dotenv
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USER=your-user
MYSQL_PASSWORD=your-password
MYSQL_DATABASE=AI-learn
DASHSCOPE_API_KEY=your-bailian-key
DEEPSEEK_API_KEY=your-deepseek-key
JWT_SECRET=replace-with-a-random-secret-at-least-32-characters
```

中国内地百炼兼容接口使用 `DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1`，Embedding 模型使用 `text-embedding-v4`，本项目固定 1024 维。`.env` 已被 Git 忽略，不得提交、截图或写入日志。

智能混合模式还需要 `TAVILY_API_KEY` 和 `WEB_RESEARCH_ENABLED=true`。私有模式不调用 Tavily；混合模式传给 Tavily 的内容只能来自用户原始主题和公开术语，禁止包含文档片段、原文件路径或 Chroma collection 名称。

## 3. 安装与迁移

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
mysql -u root -p < sql/migrations/004_add_private_knowledge_base.sql
```

迁移仅新增 `knowledge_bases`、`knowledge_documents`、`document_ingestion_tasks` 三张表，不修改现有核心闯关表。首次部署前确认后端进程对以下目录有读写权限：

- `backend/uploads/knowledge`
- `backend/data/chroma`

## 4. DOC / Apache Tika

旧版 `.doc` 通过 Apache Tika 解析。生产环境建议单独部署并预热 Tika Server，然后配置：

```dotenv
TIKA_SERVER_ENDPOINT=http://127.0.0.1:9998
```

没有可用 Tika 服务时，PDF、DOCX、Markdown 不受影响；DOC 会进入失败状态，并提示用户另存为 DOCX 后重试。Tika 首次自动启动可能需要下载运行文件，不建议把首次下载留到线上请求时发生。

## 5. 启动与健康检查

```powershell
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000

cd ..\frontend
npm install
npm run build:weapp
```

微信开发者工具导入 `frontend`，其中 `project.config.json` 已声明 `miniprogramRoot: dist/`。不要直接把 `dist` 作为独立项目导入。

启动后检查：

1. `/api/v1/health` 返回 `code=0`。
2. 登录后能创建知识库，并上传不超过 10MB 的测试文档。
3. 文档状态依次进入解析、分块、向量化和就绪；页面每 8 秒刷新处理中状态。
4. private 出题的每道题至少显示一个私有文档名和页码/章节。
5. mixed 出题以私有资料为必要依据，公开资料只能补充背景。
6. 删除知识库后，历史闯关仍保留生成时的安全来源快照。

## 6. 备份与恢复

备份必须在同一时间点覆盖：

- MySQL `AI-learn` 数据库；
- `backend/uploads/knowledge` 原文件目录；
- `backend/data/chroma` 向量目录。

恢复时先恢复 MySQL 和原文件，再恢复 Chroma。若 Chroma 丢失但原文件仍在，可对失败或需升级的文档调用 reindex 重建；不要只恢复 Chroma 而缺少对应 MySQL 授权记录。

单实例运行时应确保只有一个后端进程写同一 Chroma 目录。扩展为多实例前，应迁移到支持共享并发写入的向量服务。

## 7. 常见故障

- “资料不足”：降低不了安全门槛；应补充更相关的文档、换更明确的主题，或检查知识库是否已有就绪文档。
- “向量化失败”：检查百炼 Key、区域 Base URL、网络和 1024 维配置；失败后可在文档详情点“重试”。
- “DOC 解析服务不可用”：检查 Tika Server 和 Java，或把文件另存为 DOCX。
- “扫描 PDF 暂不支持 OCR”：在本地 OCR 后上传可复制文本版本。
- “知识库服务暂时不可用”：检查 `DASHSCOPE_API_KEY`、MySQL 连接以及上传/Chroma 目录权限。
- Chroma 查询异常：确认索引使用的模型和维度与当前 `EMBEDDING_MODEL`、`EMBEDDING_DIMENSIONS` 一致；不一致时重新索引。
